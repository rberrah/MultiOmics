# Raw MS preprocessing and independent validation

This document describes the two advanced workflows that intentionally remain outside the browser-only calculation path: standards-based raw mass-spectrometry preprocessing and evaluation of frozen predictions on an independent validation cohort.

## 1. Raw LC-MS / GC-MS preprocessing

### Supported input boundary

The reference R engine processes open exchange files directly:

- `mzML`
- `mzXML`
- `CDF` / `netCDF`

Proprietary acquisition formats (`.raw`, `.wiff`, `.d`, `.baf`, `.tdf`, etc.) are deliberately **not parsed directly**. Convert them locally to `mzML` with ProteoWizard `msconvert` or a validated vendor exporter. This avoids pretending that a web application can provide complete, platform-independent vendor reader support.

Conversion is a data-management step, not a scientific normalization step. Whether centroiding / peak picking should occur during conversion depends on the acquisition mode. The generated `msconvert` plan therefore records the requested filters and warns that centroiding must be justified for the instrument method.

### Reference pipeline

`raw_ms_processing.R` uses the current Bioconductor MS stack:

1. `MsExperiment::readMsExperiment()` — import spectra and sample annotations;
2. `xcms::findChromPeaks()` with `CentWaveParam` — chromatographic peak detection;
3. `xcms::adjustRtime()` with `ObiwarpParam` — retention-time alignment when multiple files are present;
4. `xcms::groupChromPeaks()` with `PeakDensityParam` — cross-sample feature correspondence;
5. `xcms::fillChromPeaks()` with `ChromPeakAreaParam` — targeted filling of missing chromatographic peak areas;
6. `xcms::featureValues(..., value="into")` — feature × sample peak-area matrix.

Blank injections are retained in the experiment so downstream blank-ratio QC remains possible, but their `sampleGroups` entry is `NA`; a blank cannot define a biological chromatographic feature by itself. Pooled QCs can form their own correspondence group.

The default centWave / Obiwarp / peak-density parameters are reproducible starting values, **not universal instrument settings**. Confirmatory work should prespecify or justify the acquisition-specific parameter set.

### CLI

Prepare a manifest, for example:

```csv
raw_file,sample_id,condition,sample_type,injection_order
raw/S01.mzML,S01,control,biological,1
raw/QC01.mzML,QC01,,pooled_qc,2
raw/BL01.mzML,BL01,,blank,3
raw/S02.mzML,S02,treated,biological,4
```

Install the optional raw-MS dependencies:

```bash
Rscript multiomics-engine/install_backend_dependencies.R
```

Run with the recorded defaults:

```bash
Rscript multiomics-engine/run_raw_ms.R raw_ms_manifest.csv results/raw-ms default
```

Or provide a JSON file containing overrides for `peak_detection`, `retention_time`, `correspondence`, `gap_filling`, or `quantification`.

Outputs include:

- `metabolomics_peak_area.csv` — matrix that can be loaded by the ordinary multi-omics tool;
- `metabolomics_feature_definitions.csv` — m/z / retention-time feature definitions exposed by xcms;
- `raw_ms_sample_sheet.csv` — input sample information plus the xcms grouping used;
- `raw_ms_processing_manifest.json` — exact parameters, package versions and high-level QC counts;
- `xcms_processed_experiment.rds` — processed R object for expert inspection / reanalysis.

The raw-MS stage produces **features**, not metabolite identities. Compound annotation / identification and confidence grading remain separate from peak detection.

## 2. Independent validation of frozen predictions

Nested cross-validation and repeated CV remain internal validation. They are useful for model selection and internal performance estimation but do not prove transportability to another cohort.

`external_validation.R` therefore takes the opposite approach: it **does not fit a model at all**. It accepts outcomes and predictions that were already generated by a frozen model. No feature selection, hyperparameter tuning, scaling estimation or coefficient fitting is performed on the validation cohort.

### Supported endpoints

- binary: AUC, Brier score, log loss, calibration intercept and slope when probabilities are supplied;
- continuous: RMSE, MAE, R², calibration intercept and slope;
- count: continuous prediction metrics plus mean Poisson deviance;
- survival: Harrell C-index using supplied risk scores;
- multiclass: accuracy, balanced accuracy, log loss and macro one-vs-rest AUC.

For scalar primary metrics, a deterministic percentile bootstrap can be requested. Bootstrap samples in which the metric cannot be estimated are retained as missing; the implementation never repairs a failed resample by refitting the model.

### External-validation naming guardrail

The software cannot prove cohort independence from a CSV file. The analyst must explicitly assert `independent_cohort: true` and support that assertion with study provenance. Without this assertion, the report status is `independent_status_not_asserted`, even though the supplied predictions can still be evaluated.

**Frozen-prediction cohort coverage is now explicitly audited.** If a
`subject_id` column is supplied, IDs must be nonempty and unique: repeat
measurements of one patient cannot be silently counted as independent
validation subjects. If no `subject_id` is provided, the report indicates
`subject_identity_audit.status = not_verifiable_without_subject_id`;
the software cannot verify duplication from an anonymous CSV.

The audit distinguishes `cohort_coverage.submitted_rows` from
`evaluated_rows` and `excluded_rows`. Missing outcomes, nonfinite
predictions, or non-estimable metrics can still produce partial descriptive
statistics, but they cannot receive the status `external_validation`:
instead, the result is labelled `external_validation_incomplete` with an
explicit on-screen warning. Impossible binary probabilities outside [0,1]
are rejected rather than silently clamped.

These are **necessary software safeguards, not sufficient scientific proof**:
a file without stable IDs or with a complete set of numbers may still have
overlapping patients, unrepresentative enrolment, data leakage, treatment
confounding, or a development-derived choice of outcome/threshold.
Provenance must still be reviewed independently.

### CLI example

`predictions.csv`:

```csv
subject_id,outcome,prediction
V001,0,0.12
V002,1,0.81
V003,0,0.20
V004,1,0.74
```

`validation.json`:

```json
{
  "outcome_type": "binary",
  "prediction_column": "prediction",
  "outcome_column": "outcome",
  "prediction_kind": "probability",
  "independent_cohort": true,
  "cohort_label": "Independent centre B",
  "bootstrap_repetitions": 1000,
  "seed": 20260928
}
```

Run:

```bash
Rscript multiomics-engine/run_external_validation.R predictions.csv validation.json results/external-validation
```

Outputs:

- `external_validation_report.json` — endpoint, metrics, bootstrap interval and the independence boundary;
- `external_validation_summary.csv` — compact machine-readable summary.

For a publication, retain the frozen model/version, exact preprocessing specification, prediction file and cohort provenance next to this report.

## 3. Reproducibility boundary

The browser analysis now calculates SHA-256 locally for the exact uploaded metadata and omics files and stores them in `reproducibility.cryptographicInputs`. This is separate from the historical deterministic FNV-1a application fingerprint. The latter remains useful for application-level change detection; SHA-256 is the archival integrity identifier.

The reference R backend additionally records R/platform/package versions. Raw-MS manifests record xcms/MsExperiment/Spectra/mzR/BiocParallel versions and exact preprocessing parameters. Reactome analyses retain the database release when the version endpoint is available.

A reproducible archive should therefore contain at minimum:

1. immutable source files + SHA-256;
2. sample sheet and column mapping;
3. browser analysis JSON / methods report;
4. R environment manifest when the reference backend is used;
5. raw-MS processing manifest if mzML/mzXML/CDF preprocessing was used;
6. Reactome release/token provenance when pathway analysis was used;
7. frozen-model identifier plus independent-cohort provenance for external validation.

## Remaining boundaries

The implementation now covers open raw-MS preprocessing and a strict independent-prediction validation step, but it does not claim to solve the following automatically:

- direct platform-independent reading of every proprietary vendor format;
- optimal instrument-specific peak-picking parameter selection without expert review;
- definitive compound identification from MS1 features alone;
- proof that an uploaded cohort is truly external/independent;
- clinical generalisability without a real target-population validation dataset;
- secure public hosting of the R backend without an authenticated TLS reverse proxy and deployment controls.
