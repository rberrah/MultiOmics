# MultiOmics 1.1.0 — release boundary

**Release date:** 19 October 2026  
**Software version:** `1.1.0`  
**Intended immutable tag:** `v1.1.0`  
**Research v1 baseline retained:** `54dc8f0f8284cf970ed1a5be0533a298ae27639d`

MultiOmics 1.1.0 is a **post-Research-v1 hardening release**, not a new claim of universal statistical or clinical validation. Research v1 / 1.0.0 remains the frozen baseline for the original qualification scope.

## What 1.1 adds

1. Researcher-visible separation of browser exploratory, mixed and complete native-R numerical sources.
2. Explicit result-level scientific limitations, including the known DESeq2 global-null calibration limitation.
3. A stricter `DOWNSTREAM_EXCHANGE_V1` handoff that distinguishes **structural exchange validity** from **PK readiness** and never invents dose/concentration history.
4. Independent consumption of the exchange by the current pinned Omics2PK reader, including mapped metadata, transposed matrices, missing values and quantitative molecular time.
5. A prespecified DESeq2 whole-study null-tail diagnostic that supports dispersion estimation as one contributor to anti-conservative tails in the tested generators, without changing production DESeq2.
6. A prespecified independent Sacurine raw-LC-MS comparison using xcms and a pinned OpenMS FeatureFinderMetabo pipeline. The comparison reports reciprocal-unique m/z–RT concordance without a post-hoc success threshold and without claiming chemical identity or pipeline superiority.

## Claims deliberately not added

MultiOmics 1.1.0 does **not** claim:

- universal nominal 5% FDR control;
- automatic biological validity of pathway or multi-omics findings;
- validated metabolite identities or concentrations from raw feature coordinates;
- interlaboratory analytical validation;
- that a schema-valid individual omics score is a validated PK/PD covariate;
- automatic PK readiness from molecular timing metadata;
- medical-device, clinical-decision-support or biomarker certification.

## Open scientific limitations retained

- **#44 — DESeq2 null calibration:** remains a visible known limitation, not a hidden test failure.
- **#47 — LC-MS analytical validation:** independent preprocessing evidence is useful but standards, annotation, quantitative accuracy and interlaboratory work remain beyond this release.
- **#20 — MultiOmics → Omics2PK biology:** technical interoperability is qualified; predictive/biological PK utility requires genuine subject-matched omics + dose/concentration data and external validation.

These issues are **not release blockers** because 1.1.0 explicitly excludes the corresponding stronger claims.

## Release integrity

Before the final `v1.1.0` tag is created:

- `package.json`, `package-lock.json` and `CITATION.cff` must report 1.1.0;
- Research v1 files and the frozen `release/research-v1.0.0` reference must remain unchanged;
- standalone JS/Svelte/browser qualification must pass;
- native-R contracts must pass;
- Research v1 scientific-boundary gate must pass;
- survival native-R qualification must pass;
- the current Omics2PK consumer contract must pass;
- the independent Sacurine xcms/OpenMS comparator must pass on the final source combination;
- the release-integrity gate must pass.

## Public-site handoff

The public `rberrah.github.io/multiomics/` build remains a separate deployment. It must pin the exact final 1.1.0 source SHA and rerun its mount/browser checks. It must never track a moving MultiOmics branch.

## Change policy after 1.1.0

After the tag:

- no scientific-method change is part of 1.1.0;
- dependency/runtime updates require requalification and a later patch/minor release;
- documentation corrections must not broaden scientific claims;
- new datasets, methods or omics→PK biological-validation experiments belong to a later release/research programme.

The purpose of this freeze is to stop continuous platform expansion and move the main scientific effort toward **genuine Omics + PK validation in Omics2PK**.
